# 游戏底层自然规律元设计

版本：0.7

修订日期：2026-11-02

用途：供没有项目历史上下文的设计者或AI，独立生成一套原创、可玩、计算简单的游戏自然规律。

状态：生成与验收规范。设计论证、算法审查、可执行原型和实测结果应分别记录。

## 0. 核心任务与设计优先级

为共享、持久的多人游戏创造一套具有多种非现实作用的自然。玩家应能借助这些规律，直接完成现实世界中不成立的操作，创造新的装置、组合、探索方式与社会活动。

核心成果是新的因果关系及其可操作后果。每条核心规律应能够用少量状态、明确算子和有界计算执行，并能通过简单器具或组装被玩家利用。材料、化学与制造围绕这些规律展开。

设计顺序：

~~~text
想让玩家获得的新操作与新可能性
→ 原创基础规律及其直接计算表达
→ 简单装置、控制与跨规律组合
→ 承载和调节这些作用的材料
→ 必要的加工、化学、资源与规模化
→ 共同规则、玩家负担与计算预算复核
~~~

以下要求具有优先级：

1. **原创能力必须实际改变玩法。** 不能只把现实材料、工业设备和技术史改名。
2. **计算成本与玩家操作负担必须低。** 这是基础规律的设计条件，不能全部推给后续优化或界面自动化。
3. **规律必须可理解、可实验、可组合。** 简单规则可以产生丰富用途。
4. **世界内部必须一致。** 一致性依据本世界明确选择的公理和更新规则，而非默认继承现实世界全部定律。
5. **材料与化学提供支撑。** 只展开能够改变玩家选择、装置行为或资源利用的细节。

只要核心原创性、直接可玩性或有限计算不合格，就应修改基础规律。不能用更长的元素表、更完整的工业史或更多化学反应抵消这些问题。

## 1. 游戏背景与自然的建模边界

### 1.1 约公元1000年的开局

游戏初始生活方式、社会规模、常见器具和普通制作能力以约公元1000年为参照。聚落、城镇、手工生产、农业、交换与运输构成容易理解的生活背景。

这个年代不限制自然规律的种类，也不要求原创作用等到某个工业时代才出现。居民可以在缺乏完整理论的情况下，直接利用天然材料、简单连接或经验操作产生的奇异效果。至少部分核心非现实能力应能在开局环境或简单器具中接触和使用。

候选需要解释日常生活为何大体稳定，但不要求奇异自然在开局全部沉默。稳定可以来自规则的适用对象、连接关系、作用模式或有限影响范围，不必一律诉诸极端稀有材料、深层提纯和精密控制。

后续技术发展由本世界规律展开。开局参照不规定未来技术上限，也不规定必须重演现实文明的发现顺序。

### 1.2 共享且持续演化的世界

玩家、NPC、自然环境、生产设施与离线过程作用于同一套世界状态。知识、设备和材料可以传播；后来者能够采用已被发现的规律与成熟方法。

一次独立采样生成一个候选世界。候选之间可以采用不同规律；同一运行世界内，适用条件相同的对象按同一版本的规则结算。任务、账号身份、研究进度和界面状态不得偷偷改写自然结果。

自然系统为探索、交通、建造、生产、战争、情报、身份等玩法提供基础，不要求在本任务中编写完整剧情、职业和经济制度。

### 1.3 简单模型可以直接就是基础自然

物体级、装配体级、连接级、区域级和有限状态规则，都可以作为本世界的基础公理。它们不必被解释为对另一套未实现的微观现实的近似。

普通移动、重力、碰撞、接触、燃烧或材料损坏，可以采用简明的有效规则。原创规律可以直接改变运动更新、约束、作用目标、空间关系、状态转移或生成量，不必先还原为现实的力、热、压力与化学过程。

“统一自然”要求所有规则在同一个世界中兼容结算。它不要求只有一种基本作用，不要求所有现象归于同一个场，也不要求通过原创元素重新推导全部日常物理。

一种材料可以天生具有某种非现实作用。只要参与条件、作用对象、更新方式与组合语义明确，就不必再为它搭建一套类现实场论或复杂化学解释。

### 1.4 允许改变现实的基础假设

候选可以自行定义新的运动关系、作用范围、连接方式、能源、物质生成与消失规则、时间响应或生命相关状态。瞬时作用、无需中间介质的关系、持续供给、无运行消耗的固有性质和自动稳定，都可以成为明确的基础规律。

现实中的能量守恒、动量守恒、反作用形式、局域传播、熵增或材料构成，不是本规范自动施加的总约束。选择使用哪些量、保持哪些不变量，应由候选明确声明。

改变现实公理不等于允许运行时任意编写结果。所有特殊作用仍需有稳定定义、适用边界、明确状态变化与可复现的操作证据。具体责任见§6。

## 2. 原创物理的最低覆盖与新颖性判定

### 2.1 首轮必须展示多种非现实能力

默认首轮候选至少展示：

- **六类具有实质差异的非现实可操作能力**，覆盖至少四种不同的玩家问题。
- **三个跨能力组合演示**，涉及至少四类能力，并产生单独使用时没有的操作方式或结果。
- **两类在代表开局中通过简单操作实际可用的能力**，所需材料、部件与条件当时即可取得，使玩家在复杂制造之前就能利用新自然。

这是本轮候选的展示覆盖，不是规定六种元素、六种基本力、六个时代或六套独占设备。少数共同公理可以导出多种合格能力；关键是能说明不同的干预、因果结果和组合关系。

玩家问题可涉及移动、支撑、运输、远近作用、动力、观测、控制、保护、储存、物质组织、空间使用或其他候选提出的领域。这些词不是必填能力清单，也不指定具体实现。

### 2.2 按实际能力去重

以下差别通常不单独计入原创覆盖：

- 相同作用更换名称、颜色、材料外观或对象皮肤。
- 同一效果只调整功率、效率、强度或普通工作范围。
- 同一过程拆成多个阶段并分别命名。
- 把同一操作分别用于武器和工具，而操作关系没有变化。
- 同一个装置换成人工、NPC或自动化执行。
- 多个装置并排工作，结果只是互不影响的效果相加。

非常简单的方程、一个符号或一个连接规则的改变，也可能产生根本不同的能力。不能用数学形式是否复杂判断原创性；应看可达状态、玩家操作与因果关系是否发生定性改变。

玩家问题按实际成功条件和所需决策区分，不按行业、对象名称或叙事情境重复计数。组合演示按能力间的状态依赖、操作关系和新增结果区分；同一依赖关系换名称、对象或场景，不重复计数。交付时列出能力、所解决问题、因果对照与组合编号的对应关系。

### 2.3 每项能力提交因果对照

每项核心能力必须回答：

1. 玩家改变哪个实际状态、物体关系或操作条件？
2. 世界因此发生什么可以观察的变化？
3. 关闭这条原创规律、保留普通技术后，哪项能力消失或发生根本改变？
4. 什么简单操作能区分“该规律存在”和“只有普通材料与普通技术”？
5. 这个差异怎样带来有价值的行动、选择或组合？

现实机制改名、只改善现实材料指标、只给常规工业加效率的规则，可以作为辅助内容，但不足以承担候选的主要原创性。

对照不要求证明现实宇宙中绝不存在任何相似结果。需要明确证明：本候选承诺的操作及其关键因果关系由新规律直接产生，没有把关键工作重新交给另一套常规工程系统。

### 2.4 规律应能迁移到新组合

作用应依据可检查的性质、状态、连接或关系施加，而不是只因对象具有某个预设道具名。

一类本源材料独有某种作用是允许的；将它装入不同物体、改变方向、数量、关系或控制方式时，应按同一规律得到相应结果。不能仅开放几张固定配方，然后把其他相同条件的组装判为无效。

不要求所有材料都响应每条规律，也不要求所有能力两两相容。需要明确哪些能组合、哪些会冲突，以及玩家能怎样发现这些关系。

## 3. 基础规律的直接执行合同

### 3.1 每条核心规律使用一张规则卡

~~~text
LawCard {
  id_and_causal_difference
  applicability_and_target_selection
  minimal_state_and_units
  conditions_and_player_controls
  direct_update_operator
  composition_and_conflict_rules
  sources_sinks_and_selected_invariants
  observable_results_and_feedback
  stable_operation_and_failure_transitions
  runtime_scope_and_cost
  simple_demonstration_and_tests
}
~~~

每个字段说明的是责任，允许使用等价的表格、公式或伪代码表达。没有采用的概念明确写为“不使用”，不必为了填表增加材料、燃料、场或状态。

### 3.2 直接算子必须能够真正结算

可统一写作：

~~~text
(next_states, finite_events) =
    ApplyLaw(relevant_states, operations, elapsed_time)
~~~

必须说明实际读取什么、更新什么、作用于哪些对象，以及如何产生有限后续事件。每个派生量都应能追溯到已定义状态和有界算法。

不能用“按真实受力计算”“由材料稳定度决定”“求出场分布”“达到平衡后输出”等未定义黑箱，代替核心作用的运行规则。一个短公式如果依赖未说明的连续场、结构应力或微观反应求解，仍然不是低成本规则。

无需为每种作用计算现实意义上的力、功、热和动量。若采用这些量，应说明其更新；若直接使用运动目标、约束状态、关系转移或效果容量，也可以成为完整规则。

### 3.3 同时作用与组合必须明确

至少说明：

- 多个来源作用于同一对象时怎样合成、竞争、封顶或切换。
- 两条规律读取和写入同一状态时采用什么结算顺序。
- 一个作用产生的事件何时能触发下一作用。
- 循环关系怎样处理，如何避免同一步无界递归。
- 断连、停机、拆分、损坏或目标消失时，当前状态与待执行事件怎样结算。

可以使用分阶段读写、有限次数传播、规则优先级或明确的组合算子。优先级应属于公开的自然规则或统一执行语义，不能在某个玩家成功组合以后临时改变。

组合演示应给出状态或条件的依赖关系。不能仅列出“可以用于交通、战争和工业”而没有实际因果连接。

### 3.4 直接感知和精确控制可以是自然能力

观测结果仍需来自世界状态或已定义信号，但允许规则直接提供精确读数、目标锁定、状态指示或稳定控制。并非所有仪器都必须有噪声、量程限制、积分时间和采样扰动。

只有当不确定性、测量代价或扰动构成有价值的玩法时，才加入这些机制。玩家不知道规律，不等于仪器必须故意给出模糊结果。

## 4. 从基础规律开始控制计算成本

### 4.1 选择最低必要的计算单位

优先采用整物体、装配体、材料批次、活动装置、已登记连接或少量区域作为更新单位。

有限状态、代数式、短查表、离散事件、稀疏关系和解析时间推进都可以是精确的基础定义。无需先创建微观粒子，再将它们近似掉。

每条规律只维护会改变实际行为、可观察结果或玩家决策的状态。没有进入本世界模型的现实微观细节，不承担持续保存与更新义务。

### 4.2 装配时计算能力，运行时更新整机

默认将构造与运行分开：

~~~text
组装、拆装或相关损坏时：
部件与连接 → 整机能力、活动关系与有限运行状态

日常运行时：
整机状态 + 玩家目标 + 少量相关环境输入 → 下一状态
~~~

部件可以直接赋予或改变所属整机的运行能力。除非某项布局或结构细节被明确选为玩法变量，否则不逐帧计算每个零件的实际受力、热传导和材料变形。

增加装饰和被动构件通常不增加同等数量的每帧物理单元。相关变动可以触发局部重算，但不能每步重新求解完整结构。

碰撞和占位仍需明确，可以使用有限的代理形状、包围体或简化部件。不得在能力更新已聚合之后，又默认采用全部细节碰撞，悄悄恢复逐零件计算成本。

### 4.3 非接触与非局部作用可以采用稀疏关系

作用可以按已登记端点、对象绑定、局部查询、区域索引或明确的目标选择规则执行。物理距离不自动等于计算路径长度。

一条直接连接可以无需沿途模拟介质或连续场。需要说明关系如何建立、对象如何寻址、是否有延迟、怎样解除、怎样处理争用和端点失效。

不得因为世界允许远距离作用，就默认遍历全世界对象、求全部对象两两作用，或创建覆盖整个地图的高分辨率场网格。

### 4.4 每项能力都提交可审查的预算

预算至少包含：

| 项目 | 需要说明的内容 |
| --- | --- |
| 状态规模 | 每个活动对象或装配体增加哪些动态状态，数量是多少。 |
| 调用条件 | 每逻辑步、低频更新、状态变化或特定事件中的哪一种。 |
| 读取范围 | 一次更新访问多少对象、连接、区域或查询结果，数量如何受限。 |
| 工作量 | 使用哪些查表、运算、查询、列表扫描或固定阶段。 |
| 事件展开 | 一次调用最多产生什么事件，触发链与并发怎样限制。 |
| 组装变化 | 什么变化触发重算，重算涉及多大范围。 |
| 非活动状态 | 停机、远距、离线或稳定状态如何休眠或解析推进。 |
| 增长方式 | 装饰、被动部件、活动装置和连接数量增加时，成本分别怎样变化。 |

写出复杂度时，必须说明规模变量代表什么。不能把未定义的“求场”包装成一次调用，便声称每条规律是常数成本。

还需检查整个运行场景的活动对象、连接、动态生成对象与待执行事件如何随时间增长。单次调用有界、同一步没有递归，不代表跨时间步不会出现指数扩展或无限积压。持续生成、复制、自动建连和事件传播都需说明总体增长及其可执行边界。

可以采用批次聚合、休眠、合并结算、有限承载或其他与玩法相容的方式控制工作量。持续增加一种数量，不必同时增加同等数量的活动实体。能源是否耗尽与执行是否可承受分别判断，不要求用现实燃料或损耗压制规模；但不能在超载以后临时取消已经承诺的效果。

给出一个多装置并发、长期运行和反复改装的负载场景，说明总体状态、查询、重算与待执行事件的增长方式。任何会改变玩家可观察结果的上限、延迟或调度方式，都应纳入已声明规则或统一执行条件。

不预设所有效果都必须每帧运行，也不默认每个对象每帧检查全部规律。若需要连续数值求解，应证明它确实提供不可替代的玩法，并给出具体成本边界；不能作为核心能力尚未设计清楚时的默认补救。

### 4.5 不虚构性能结论

未实现时，可以报告状态数、查询数、更新频率、事件上限与算法复杂度；不能据此宣称某种硬件上已经达到特定帧率或毫秒耗时。

研究模式与工业模式也不能成为无限增加细节的例外。提高细度必须服务明确操作，并保留与日常执行相容的低成本表示。

若采用多种求值方式，它们需保持已声明玩法状态、对象身份与事件结果的一致性。这里比较的是本世界定义的规则，不是未实现的现实微观模拟。

## 5. 玩家负担与简单装置

### 5.1 基本玩法以组装和目标控制为主

优先使用放置、连接、定向、启停、选择模式、设置目标、替换模块等操作。玩家通过这些动作改变实际状态与关系，由规律决定结果。

每项核心能力都应有一个普通使用演示。默认原型目标是：初次有效演示只需少量有意义的设置或连接动作，机制特有的调节项不超过三个，日常运行不需要同时手工维持多个稳定变量。

该预算评估的是需要理解的独立决策，不是按钮数量。不能把十个精密参数打包成一个“综合调节”按钮，仍在背后要求复杂模型。

分别列明取得或制造条件，以及取得之后的普通使用步骤。后期发现与制造可以有门槛，但不能因此增加每次使用的无效负担；§2与§8要求的早期能力仍须有真实可达路径。

高级构筑可以增加选择，但不能把所有基本奇异效果都放在精密装配、严格配比、持续校准和多级提纯之后。

### 5.2 稳定和宽容可以是原生性质

规律可以直接具有稳定区间、自动保持、迟滞、饱和、自动对齐或状态锁定。装置也可以接收玩家目标并直接完成规则允许的控制，不要求另建一套现实传感器与控制工程。

应说明普通材料与合理装配偏差怎样影响效果。默认让常见偏差降低性能、改变某个特征或给出明显提示，而不是立即使所有基本功能失效。

自动稳定不必天然昂贵，也不必永远消耗额外燃料。它可以是可靠、廉价的基础能力。

### 5.3 限制应来自玩法选择

一项能力不必同时承担燃料、废热、冷却、污染、维修、结构应力、稀有配料和漫长加工等全部负担。

根据实际设计，选择少量能产生有意义决定的边界。边界可以涉及作用对象、连接关系、模式冲突、容量、范围、时机、可干扰性、资源或其他原创状态，不强制沿用现实工程的成本种类。

部分基础能力可以没有运行消耗，其乐趣来自用途与组合。也允许新技术淘汰旧工艺，不为永久维护旧设备价值而增加隐含成本。

### 5.4 提交普通使用流程与恢复流程

对每个核心演示，说明：

- 从哪里取得初步可用的材料或部件，开局路径是否成立。
- 玩家怎样组装、启动和控制。
- 哪些状态需要观察，反馈是否明确。
- 常态运行需不需要持续人工介入。
- 一次常见误操作会怎样，怎样恢复。
- 深化研究会增加什么能力或选择。

没有玩家测试时，应标注为纸面操作预算，不能宣称新手已能在某个时间内学会。

### 5.5 至少一个综合装置必须证明简单性

候选需展示一个由多条原创能力共同支撑的可组装装置。它应承担明确的移动、运输、建造或其他持续任务，并能从启动运行到停止恢复。

主要效果必须由原创规律直接产生。若设计已经承诺某种运动或空间能力，就不能把实现该能力的关键问题重新留给一套未定义的现实工程模型。

给出整机运行状态和控制方式，说明增加被动结构与增加活动装置时的计算成本差别。基本演示能运行以后，再讨论高级性能或复杂制造。

## 6. 内部一致性、原创来源与合法生成

### 6.1 先声明公理，再检查公理

候选应说明：

- 哪些量在什么操作或范围内守恒。
- 哪些量可以由规律产生、消失、复制或转化。
- 哪些对象关系可以直接建立或非局部更新。
- 多种规则共同作用时怎样执行这些声明。

没有选择的现实守恒律，不构成隐含否决条件。不能要求所有原创作用补造反冲体、现实燃料、隐藏储能、传播介质或热耗散，才能被视为完整。

若候选明确采用某项守恒律，就必须在所有适用组合中遵守；若存在例外，则应将例外作为公开的另一条规律，而不是临时修正结果。

### 6.2 基础来源可以直接成立

需要数量时，可使用这样的通用账目：

~~~text
quantity_next =
    quantity_now
    + rule_defined_generation
    - rule_defined_removal
    + transfers
~~~

生成项可以就是基础公理，不必还原为另一个守恒量的损失。持续供给可以在时间上不耗尽；某种固有作用也可以根本不使用“储能”这个状态。

应明确作用如何发生、每次执行怎样结算，以及是否存在输出、使用、连接或承载边界。限制服务于玩法、数值定义和世界稳定；不要求每项强效果付出等价现实能耗。

本世界若允许合法的物质生成、复制或净能量收益，应依照规则登记实际结果。不能仅因现实中把某种循环称为永动机，就自动认定它违规。

### 6.3 防止重复结算，不禁止自然创造

| 情形 | 处理原则 |
| --- | --- |
| 同一事件因重复打开界面或重试而执行两次 | 禁止重复结算。 |
| 同一既有物体跨区、交易或读档后出现两份身份记录 | 修复对象唯一性和交接事务。 |
| 只把库存记录拆成多行，实际状态未变，效果却增加 | 表示方式造成漏洞，应修正结算。 |
| 玩家执行规则允许的真实分割、制造、生成或复制 | 按已定义状态变化结算；允许产生规则规定的新结果。 |
| 多条规律组合后产生原先未列举的有益效果 | 先验证是否遵守公理，再评价玩法；不能因未预想就直接判作弊。 |

几何、表面积、连接或状态真正改变时，结果可以改变。需要区分真实操作和纯粹改变数据库表示。

### 6.4 未定义的组合必须有明确处理方式

规则应给出适用范围、合成规则或明确的无作用情形。运行时不能由叙事AI为每个新组合临时生成一条自然法则。

可以用有限表格、通用算子或稳定的优先级处理组合。对当前未支持的操作明确界定，后续扩展按规律版本管理；不能用“未来再模拟得更真实”作为当前核心玩法的依赖。

## 7. 材料与化学服务于物理规律

### 7.1 物理先行，材料响应后置

先定义什么作用存在、怎样发生、怎样计算和怎样组合，再确定哪些材料承载、激活、改变、限制或记录这些作用。

材料可以直接具有基础性质，不要求每种特殊能力都先通过复杂反应才能获得。普通材料也可以参与原创作用；天然复杂材料可以先被利用，之后才研究组成。

材料问题可以促使物理规则迭代，但修改后应重新检查原创性、简单性和组合。不能通过不断追加化学细节，掩盖核心规律尚不能直接运行的问题。

### 7.2 最小材料定义

第一版只需为支撑核心演示的材料定义：

~~~text
MaterialProfile {
  relevant_law_responses
  quantity_or_capacity_semantics
  meaningful_internal_states
  simple_occurrence_or_acquisition
  useful_processing_changes
  substitution_and_combination
}
~~~

材料状态可以是连续量、有限档位或小型枚举。相同状态与适用条件采用相同响应；名称和天然、人工标签本身不赋予隐藏特权。

一条规律不必独占一种材料，一种材料也可以参与多条规律。是否进一步区分本源组分、物种、相、混合物和结构，由实际操作与玩家问题决定。

### 7.3 何时才展开化学

只有满足至少一种明确需要，才在核心候选中新增化学细节：

- 改变组成或相状态能够改变某条物理规律的可用性或响应。
- 一条有价值的制造、回收、检测或资源路径依赖该变化。
- 产物、副产物或环境转移带来实际玩法后果。
- 不作此区分，会使已承诺的操作结果相互矛盾。

每个新增组分、相或反应应指出：它服务哪条物理规律、哪项装置能力或哪种玩家选择。没有对应作用的细节，留在后续内容设计中。

化学可以使用符号组成、有限反应表、粗粒度相变或离散状态。它遵守已选择的本世界物理和来源规则，不必从场方程逐项推导，也不能借化学层重新引入一整套隐含现实物理。

### 7.4 保留气态能力，按需要启用详细过程

世界表示应能容纳固体、液体、气体，以及候选需要的相变和气相作用；但不要求每套候选提交完整气相工业链、真实相图或全世界压力求解。

气体可以采用区域数量、简单压力档位、容器状态或其他能支持目标玩法的有限表达。只有泄漏、壁面、蒸发、分离或沉积真正影响目标操作时，才展开相关状态与规则。

材料数据库与资源路线的覆盖范围，由核心能力和实际玩法决定。普通材料只需定义被相关操作读取和改变的性质。

### 7.5 加工保持真实状态，但不扩大无用细节

已经发生的材料变化，在中断、取样、搬运、合并和继续加工后应按模型保留。自动化和NPC可以执行成熟程序；不因换了执行者就跳过规则。

只跟踪模型明确承诺的数量和状态。若某种微量组分将用于未来提取，就在批次或区域账本中保留，不能因显示精度删除；未纳入世界物质模型、也不影响任何已定义操作的现实杂质，不必先生成再逐项维护。

加工可以是少量有意义的步骤。开放加工意味着操作读取真实状态，不意味着每次生产都必须手工展开大量中间工序。

## 8. 开局、发现与技术发展

### 8.1 从可接触的新物理出发

先布置能够支持核心规律演示的天然现象、材料或简单装置，再检验它们如何与熟悉日常生活共存。

至少两类核心能力应能在明确的代表开局中，利用当时可取得的材料、部件和条件，通过简单操作产生有用结果。仅能观察到的奇异现象不计入这两类早期可用能力。不要求各地区拥有相同能力，但须明确何种开局满足这一条件。

其他能力可以有较深的发现和制造门槛，但不能把所有非现实体验都压到漫长现实工业链的末端。

地区差异来自实际条件、材料、关系、初始知识和设备，不按地区名任意改变同一规律。

### 8.2 研究揭示控制与组合

研究可以回答：什么条件使作用发生、怎样改变目标、哪些对象响应、不同规律怎样组合、容量或范围怎样扩大，以及怎样实现稳定量产。

关键规律应有可比较的解释与鉴别操作。实验优先让玩家改变少量变量并获得清楚反馈，不默认要求精密实验室或长时间重复劳动。

不强制每条规律采用相同发现顺序。经验利用、知识传播、贸易、合作、购买设备和自动化都可以改变进入路径。

### 8.3 发展由新物理重新组织

候选需说明至少一条技术或社会活动路径，因原创规律而采用不同于常规现实工业的组织方式。不能只在现实科技树末端添加特殊材料。

可以跳过某些现实工程难题，也可以产生本世界独有的新问题。新的问题应由已有规律导出，不为维持熟悉的时代顺序而额外制造障碍。

物质获取、设备控制、连接组织、适用范围、知识和可制造状态都可能成为发展重点；不预设所有进步都是更高温度、更高纯度、更大压力或更多反应步骤。

### 8.4 稀缺与劳动可以改变

资源的有效稀缺由实际分布、取得方式、处理能力和目标规格决定。新技术可以消解旧稀缺、扩大供应、替换天然材料或降低重复操作。

不要求每种原材料始终稀缺，也不要求每种强能力持续消耗资源。核心资源需要说明可达路径和大致限制；全面矿物化学、全球经济和价格预测不属于首轮物理候选的必交内容。

自然模型不自动保证各阵营均等。公平、体验保护与运营规则应明确放在相应系统，不以暗改同一实验结果实现。

## 9. 共享执行、持久状态与系统接口

### 9.1 已定义状态具有权威性

区分自然更新、观测呈现和社会响应：

~~~text
world_next = ApplyDefinedLaws(world_state, operations, events)
observations = Observe(world_state, observing_operations)
social_actions = Decide(observations, knowledge, institutions)
~~~

观测可以准确，也可以按规则有误差；社会系统可以提供个性化线索。它们不能因为玩家身份或剧情需要，偷偷改变已定义的物理真值。

通过规则更新运动、容量、关系或材料属性是正常自然执行。只有缺乏已声明规则、随任务或叙事任意改值，才构成绕过自然模型。

### 9.2 拆分、合并、保存与搬运

候选应对已采用的对象和能力说明：

- 分割与合并怎样改变数量、容量、内部状态和关系。
- 内容物和绑定状态怎样随容器或对象移动。
- 跨区、交易、离线与读档如何保持对象身份和事件唯一性。
- 停机、暂停、关闭界面与自然停止之间有什么区别。
- 已发生的生成、消耗、转移和状态变化怎样保存。

只结算实际定义的过程。普通物品可以默认稳定，不必让每件物品在背包中持续反应、泄漏、衰变或积压压力。

如果某个活跃过程确实持续变化，应采用有限事件或解析推进处理，不能把离线、换容器或转移区域变成未声明的冻结或重复领取方法。

### 9.3 生命、信息与特殊关系按需要建模

若候选采用生命、灵魂、历史、身份或空间关系机制，应区分物质载体、信息记录、持续动态结构、对象身份与特殊关联。

复制信息、生成新物体和延续同一个身份，不因使用相同名称而成为同一操作。是否允许复制、转移或非局部关联，由候选自己的基础规律决定，不预设唯一继承者或一概不可复制。

只为纳入玩法的机制建立必要状态，不要求所有候选完整模拟生命、意识或身份形而上学。

### 9.4 游戏接口保持边界

技能和组织条件可以改变实际操作、知识、设备与选择；不能作为同条件下任意修改结果的隐藏系数。

材料的功能、耐久和市场价值与其已建模的数量分别处理。损坏怎样改变内容物与状态，由规则定义；经济系统不应把同一份物质的反复加工重复记作新创造的同份资产。

AI可以组织生产、提出方案或控制装置。它不能在运行时随意增删自然公理。显式版本变更与管理事件应与自然演化分开记录。

## 10. 生成顺序与交付预算

### 10.1 第一优先交付物理骨架

默认先形成一份可以独立审查的物理骨架，按以下顺序输出：

1. 本世界最重要的非现实因果差异，以及§2规定的能力覆盖。
2. 核心规则卡，包括直接更新算子。
3. 普通使用演示、因果对照和跨能力组合。
4. 综合装置的组装、控制、整机状态与计算预算。
5. 支撑这些演示的最小材料响应。
6. 开局使用路径、关键研究问题与未验证事项。

骨架应已经说明核心效果怎样运行。不能把可玩性和计算定义留成以后填补的空白，却先提交完整化学网络。

### 10.2 再按因果需要扩展材料与化学

核心骨架通过自身的新颖性、操作负担和计算范围检查后，再扩展材料获取、加工、必要化学、资源变化与规模化。

检查是生成过程内的质量关卡，不要求自动停下来向用户请求批准。若关卡失败，应先修改核心规律，不继续堆积配套细节。

完整候选应包含支撑所承诺能力的足够材料与过程，但不要求补全世界所有物质。化学附录不能改变已经声明的物理公理而不重新核验。

### 10.3 首轮内容预算

首轮正文至少约三分之二用于原创规律、直接玩法、组合与运行计算；化学细节至多约六分之一。其余篇幅用于必要背景、初态和验证范围。

比例用于防止输出重心偏移，不能替代实际质量门槛。重复“大胆原创”“容易计算”等口号不计为物理设计；完整的物料表也不能证明新能力已经成立。

需要更详细的材料工业内容时，作为后续扩展单独展开。若输出空间不足，优先保全规律、直接玩法和计算合同，缩减目录与背景铺陈。

### 10.4 独立采样边界

生成当前候选只使用本文件与本次明确附加的条件，不依赖历史聊天、其他候选或旧项目文件。不得为了与未知候选不同而任意破坏自身规则。

不同采样保持相同的最低能力覆盖与交付合同，但不预先分配固定元素、主题、能力答案或技术路线。模型自行选择具体的非现实因果结构。

同一候选可以持续修订自己的设计。不同候选之间的信息隔离由调用环境保障，不能仅凭一句“忘记以前”视为已经实现。

## 11. 验收与证据

### 11.1 首要门槛具有否决权

| 门槛 | 最低证据 | 不合格表现 |
| --- | --- | --- |
| 多种原创能力 | 达到§2覆盖，每项有因果差异和禁用对照。 | 主要是现实技术换名、材料指标提升，或同一作用反复计数。 |
| 物理主导 | 关键操作直接依赖原创规律；化学为其提供支撑。 | 新规律只贡献少量增益，主要篇幅与能力仍由常规工业承担。 |
| 直接可玩 | 普通使用流程、少量调节、清楚反馈和可恢复失败。 | 基础非现实体验整体被推到长制造链之后，或普通使用依赖严苛规格、持续人工维稳。 |
| 直接可计算 | 明确状态、算子、调用范围、事件上限与规模变量。 | 把复杂求解藏进一个参数，或以“后续优化”替代运行定义。 |
| 有价值的组合 | 三个组合演示改变操作关系或可达结果。 | 只有能力清单，或只有并排安装与数值叠加。 |
| 公理一致 | 明确来源与选定不变量，组合按同一规则执行。 | 用现实定律否决已允许的原创公理，或用原创名义临时改结果。 |

任何一项不合格，都应回到核心设计修改。不能用其他项的高分平均抵消，也不能用化学完整度补分。

### 11.2 补充检查

- **开局成立：**约公元1000年的生活参照与至少两类低前置原创能力的实际使用同时成立，日常稳定有简明解释。
- **综合装置成立：**存在持续任务的运行、控制、停机和恢复过程；被动部件数量不自动变成等量高频模拟单元。
- **普通操作宽容：**合理装配偏差有明确后果，自动稳定没有隐藏的精密模拟前提。
- **原创来源合法：**持续供给、净生成、无消耗作用和非局部关系按候选公理判断，不被默认现实账目重新封禁。
- **材料必要：**每项核心化学细节对应已定义物理能力、工艺选择或可观察矛盾。
- **持久一致：**只对已建模状态承担保存义务；已发生事件不会因跨区、离线、重试或界面操作重复结算。
- **发现与发展：**知识可以传播，至少一条技术路径由新物理重新组织，技术能够减少重复劳动或改变资源约束。
- **适用范围明确：**没有采用的条件性机制不强制补齐；采用的机制必须给出边界和组合语义。

### 11.3 最小验证任务

为下列任务给出可执行操作、预期结果和失败判据：

1. 单项能力的简单演示，以及关闭该规律后的对照。
2. 多能力组合及同时作用的状态变化。若候选采用竞争或冲突机制，至少覆盖一种；未采用时，检验同时作用按既定合成规则得到的结果。
3. 综合装置完成一项持续任务，并处理一次常见误操作。
4. 增加被动结构与增加活动连接时，分别说明工作量如何增长；检查多装置长期运行和反复改装时的总体状态及事件增长。
5. 一个已建模对象经过拆分或转移、保存和恢复后，按规则继续工作。

仅当候选使用气相工业、特殊身份、物质复制或其他专门机制时，才增加相应测试。不为了验收表好看而要求候选先发明这些机制。

### 11.4 分清设计承诺与实证

| 状态 | 含义 |
| --- | --- |
| 已定义 | 已给出明确规则、状态、假设与边界。 |
| 已做静态检查 | 在列明范围内核对了依赖、状态转移、工作量或选定不变量。 |
| 已运行原型 | 实际执行了注明的实现、输入与测试。 |
| 已做性能或玩家测试 | 在说明的硬件、场景或受试条件下测量了结果。 |

没有运行就提供测试方案，不填写虚构数据。少量示例可运行，不等于整个持久世界已稳定，也不等于玩家已经认为有趣。

交付时列出规范版本、附加条件、重要物理选择、关键玩法证据、计算预算与未解决问题。最终评价首先看玩家获得的新能力，以及这些能力是否真正简单、可操作、可组合。
